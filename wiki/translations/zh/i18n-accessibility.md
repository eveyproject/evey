# 语言与无障碍

这里如实交代 Evey 在国际化（i18n）和无障碍（a11y）两方面的现状：哪些能用、怎么实现的、
哪些还没做到。这是一个由一个人开发和维护的自托管项目，**无障碍**尤其请当作
*尽力而为，而非通过认证*。

---

## 国际化（i18n）

### 什么会翻译，什么不会

- **会翻译：** 界面本身 - 按钮、菜单、设置、错误提示，以及邮件和推送通知的文案。
- **Evey 不翻译：** 媒体元数据（标题、剧情简介、类型）来自你配置的元数据提供方
  （TMDB/OMDb），语言由你设定的**元数据语言**（`EVEY_METADATA_LANGUAGE`）决定，
  与界面语言互不相干。你自己的媒体库、文件名以及一切你亲手输入的内容都原样保存。

所以界面是法语、影片简介却是英语（或者反过来）完全正常 - 这本就是两项独立的设置。

### 支持的界面语言

六种：**英语（en）**、**法语（fr）**、**德语（de）**、**西班牙语（es）**、
**中文（zh）**、**印地语（hi）**。英语既是源语言也是兜底语言：其他语言里缺失的字符串
会回落到英语，而不是显示空白或者键名。

### 工作原理

- **单一事实来源：** 仓库根目录下的 [`/i18n/<locale>/*.yaml`](../i18n)，按命名空间拆分
  （`common`、`auth`、`media`、`player`、`admin`、`errors`、`notifications`、`mobile`、
  `downloads`、`requests`）。所有端共用同一份词条。
- **服务器**加载这份词条，通过 `GET /api/v1/i18n/{locale}` 对外提供，同时自己也直接用它
  来翻译 API 错误信息和通知文案。
- **网页、移动和 TV 应用**从该端点拉取翻译（i18next + http-backend），在本地缓存，
  并让 `<html lang>` 始终跟随当前语言，好让辅助技术念对语言。
- 语言优先取自账号里的偏好设置，其次是浏览器或设备的语言（会解析 `Accept-Language`
  并去掉地区：`fr-FR` → `fr`），最后回落到英语。
- 插值和复数形式交给 i18next 处理（`{{count}}` 之类）。

### 老实说的局限

- **完成度参差不齐。** 英语是权威版本，永远是完整的；另外五种靠人工配合一个检查脚本保持对齐，
  但全新的功能可能先只有英语，翻译跟上之前一直走回落。
- **暂不支持从右往左书写的语言。** 没有阿拉伯语、希伯来语和波斯语，布局也从未按 RTL
  搭建或测试过 - 补上一种是一件实打实的工程（CSS 逻辑属性、`dir` 处理），
  绝不只是加一个翻译文件。
- **翻译没有经过专业审校。** 质量属于社区和维护者的水准，欢迎指正。
- **本地化格式只做了一部分。** 日期和数字依赖平台的 `Intl` 和浏览器区域设置，
  并没有在每个界面上都统一接好。

### 新增或修正一种语言

1. 把 `i18n/en/` 复制成 `i18n/<your-locale>/`，翻译其中的 YAML 取值（键名保持不变）。
2. 在 [`internal/pkg/i18n/i18n.go`](../internal/pkg/i18n/i18n.go) 的白名单
   （`supportedLocales`）里加上这个区域标识。
3. 各语言的键集合必须完全一致，否则一致性检查会失败。

## 无障碍（a11y）

### 现状如何

Evey 用语义化 HTML、ARIA 标签和 React Native 的无障碍属性搭建，下面几件事也是有意为之。
但它**没有**按 WCAG 做过正式审计，测试套件里**没有**自动化的无障碍测试，
也**没有**系统性地用屏幕阅读器测过。有些部分大概能配合辅助技术使用，有些大概不能。
如果你依赖辅助技术，请做好磕磕绊绊的准备，也请把具体问题报告给我们。

### 已经做到的

- **减少动态效果：** 全局遵循 `prefers-reduced-motion: reduce` - 操作系统提出这项要求时，
  动画和过渡基本上都会关掉。
- **给辅助技术的语言标记：** `<html lang>` 始终跟随当前界面语言。
- **键盘操作（播放器）：** 完整的键盘控制，配有一份屏上快捷键说明（按 `?` 调出），
  而且在输入框里打字时快捷键会被屏蔽。
- **控件带标签：** 纯图标按钮和滑块在网页端带 `aria-label`，在移动端带
  `accessibilityLabel` / `accessibilityRole`（覆盖了大部分交互控件，但并非全部）。
- **主题：** 内置五套主题（默认深色、AMOLED、深红、浅色默认、浅蓝），
  更多主题可以通过主题扩展获得。
- **Android TV：** 为遥控器导航实现了 D-pad 焦点处理。

### 老实说的缺口（尚未完成）

- **没有做过屏幕阅读器专项测试。** NVDA / VoiceOver / TalkBack 的使用流程都未经验证；
  某些自定义组件（菜单、模态框、进度条、轨道选择器）可能无法正确念出自己的状态或角色。
- **焦点管理未经审计。** 焦点可见样式，以及对话框和浮层里的焦点顺序，有些地方并不一致。
- **只测量了内置主题的对比度。** 一个单元测试
  （`frontend/packages/theme/src/contrast.test.ts`）会检验每一套随附主题：强调色、
  三级文字色和一组危险色，相对背景色和两种表面色都必须达到 WCAG AA 的 4.5:1；
  TV 应用还会再检查一遍它自己派生出来的色值。主题扩展，以及扩展在运行时注入的颜色，
  都不在检查范围内 - 自定义主题仍可能在某些地方不达标。AAA 不在目标之内。
- **应用内没有文字缩放**，只能靠浏览器或系统缩放，也没有专门的高对比度模式。
- **移动端的字幕样式能调的很少**（这是底层 `expo-video` 播放器的限制），
  不过字幕轨本身是能正常播放的。

### 如何报告问题

请告诉我们是哪个页面或界面、具体是哪个控件、你期望的行为，以及所用辅助技术及其版本。
具体的报告我们会去修；一句“它不无障碍”则无从下手。无障碍相关的修复按尽力而为处理。
