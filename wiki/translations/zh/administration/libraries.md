# 媒体库与元数据

媒体库就是一个类型加一组文件夹。Evey 扫描这些文件夹，根据文件名识别每个文件，并获取其元数据：标题、简介、海报、演员表、评分。媒体库在 **Admin → 媒体库** 中管理。

## 类型

| 类型 | 识别为 | 元数据来源 |
| --- | --- | --- |
| **电影** | 每个文件（或每个文件夹）一部电影 | TMDB，设置了密钥时由 OMDb 补充 |
| **电视剧** | 剧集、季、集 | TMDB |
| **音乐** | 艺术家、专辑、曲目 | 文件的标签；封面依次来自文件本身、专辑文件夹、Cover Art Archive（MusicBrainz），最后是 iTunes |
| **照片** | 相册、带拍摄信息的图片 | 文件本身 |

把电影和剧集放在不同的媒体库中：类型告诉扫描器要找什么。

## 文件夹是容器内的路径

文件夹选择器列出的是容器能看到的内容。使用安装页面的 compose 文件时，你的媒体文件夹是 `/media`，所以主机上的 `/srv/media/films` 文件夹对 Evey 来说是 `/media/films`。第二个挂载的文件夹（`/media2`）以同样方式添加。

## 文件命名

扫描器能识别这样的名称：

```text
/media/films/The Mirror (1999)/The Mirror (1999) 1080p.mkv
/media/films/Lantern.2010.1080p.BluRay.x264.mkv
/media/series/The Outpost/Season 01/The.Outpost.S01E05.720p.mkv
/media/series/Quiet Storm/Quiet.Storm.03x10.mkv
```

对电影来说，年份最重要。对一集来说，是 `S01E05` 或 `1x05`。发布标签（分辨率、来源、编码、音频、`VOSTFR` 或 `MULTI` 之类的语言标签、"导演剪辑版"之类的版本）会在搜索前去掉。如果你的文件带有解析器不认识的标签，把它添加到 **Admin → 服务器配置 → 解析器标记**；从下一次扫描开始生效。

## 音乐库

扫描器读取 MP3、FLAC、M4A、OGG、Opus、WAV 和 AAC 文件，并从标签中获取每首曲目的信息：标题（缺失时使用文件名）、艺术家、专辑艺术家、专辑、年份、曲目号和碟号、类型。艺术家按专辑艺术家分组，该标签为空时按艺术家分组。

**一个专辑就是一个文件夹。** 曲目按所在的文件夹分组，而不是按专辑标签：两个带有相同专辑标签的文件夹是两个专辑，拆分在 `CD1` 和 `CD2` 子文件夹中的专辑会显示为两个。请把每个专辑放在一个文件夹中；其曲目先按碟号再按曲目号排序，专辑采用大多数曲目所带的名称。

封面依次取自文件中内嵌的图片、专辑文件夹中的图片（`cover.jpg`、`folder.jpg` 或 `front.jpg`）、Cover Art Archive（通过 MusicBrainz 查找），最后是 iTunes。

## 照片库

扫描器读取 JPEG、PNG、HEIC、WebP、GIF、TIFF 和 BMP 文件。照片的相册就是它所在的文件夹（相对于媒体库文件夹）；位于顶层的照片没有相册，把文件移到另一个文件夹后，下一次扫描时它会归入该相册。拍摄日期和相机型号来自 JPEG 文件的 EXIF 数据；其他格式的照片没有这些信息。缩略图在服务器上缩放，并保存在转码缓存中。

## 新文件如何被发现

每个媒体库有三个选项：

| 选项 | 效果 |
| --- | --- |
| **实时监控** | 新建、重命名和删除的文件一出现就会被发现。定期检查（默认每 2 分钟一次）会补上文件系统没有报告的变化，这在网络共享上会发生。 |
| **启动时扫描** | 每次服务器启动时扫描一次。 |
| **计划** | 每 6 或 12 小时、每天、每周或按 cron 表达式进行一次完整扫描。 |

服务器还会通过在媒体库文件夹中写入一个存在几秒钟的探测文件，来检查它的文件夹监视器是否仍能收到事件。事件不再到达的媒体库会被更频繁地遍历，直到监视器恢复。

## 条目错误或缺失时

- **仅匹配孤立项**（按媒体库）会重试那些从未被识别的文件。速度很快。
- **从 TMDB 重新匹配全部** 会为媒体库中的每个条目重新搜索。速度慢，可以在大规模重命名后纠正旧的错误。
- 条目上的 **编辑元数据** 可以手动修改它的信息，或者粘贴正确的 TMDB 或 IMDb id。你编辑过的值会被保留：之后的刷新不会覆盖它。条目上的 **重新匹配元数据** 会丢弃你的编辑，并根据文件名重新搜索。
- **修复系列** 会把不属于任何合集的电影重新归入它们的系列，前提是该系列的其他电影已经在媒体库中。

## 合集

**合集** 把标题归在同一个名称下，对所有账户可见。共有三种：

- **TMDB 合集**：系列电影，当 TMDB 把某部电影归入其中时会自动填充。**修复系列**（见上文）会补回漏掉所属系列的电影。
- **新建合集**：由管理员手动填充的列表，在标题或选中的多个标题上使用 **添加到合集**，并可调整顺序。
- **新建智能合集**：基于 **类型**、**年份**、**媒体类型**、**评分 ≥** 和 **媒体库** 的规则，标题必须满足全部规则。其内容在每次打开时计算，因此新标题无需任何操作就会出现。

只有管理员可以创建和编辑合集。任何人都可以浏览，网页上的 **下载合集** 会把原始文件打包成一个 ZIP（最多 1000 个标题），并排除该账户的媒体库权限或年龄限制所隐藏的内容。

## 元数据密钥

Evey 自带一个 TMDB 密钥，所以元数据无需配置即可工作。其他来源是可选的；它们的密钥放在 **Admin → 服务器配置 → API 密钥** 中，在那里设置的密钥优先于环境变量中给出的同一密钥。

| 密钥 | 增加的功能 |
| --- | --- |
| TMDB（你自己的） | 使用你自己的请求配额，而不是共享配额。 |
| OMDb | 对 TMDB 了解不多的电影提供第二个来源。 |
| OpenSubtitles | 通过服务器 API 搜索和下载文件中没有的字幕（应用暂未提供此功能）。见[字幕](../playback/subtitles.md)。 |
| TheIntroDB | 来自社区数据库的片头、回顾和片尾时间：有密钥时每天 500 次查询，没有时 100 次。 |

## 片头、回顾和片尾

Evey 会标记剧集和电影的片头、回顾和片尾，这样播放器就能提供跳过。时间点在社区数据库（先 TheIntroDB，再 IntroDB）认识该条目时来自这些数据库，否则来自服务器自己对文件的分析。管理员可以手动调整一个条目的片段，或者重新运行检测。

播放器默认显示一个**跳过**按钮。**自动跳过片头**（**Admin → 服务器配置 → 服务器设置**，默认关闭）会让每个播放器自动跳过。
