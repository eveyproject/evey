# 媒体健康

**Admin → 媒体健康** 读取你的媒体库中的每个 MKV/WebM 文件，并给每个文件一个唯一的答案。目标是一个会逐渐清空的页面：Evey 能修复的，它就修复；其余的只提一次，并且可以标记为已看过。

## 两种结论

| 结论 | 含义 | Evey 的处理 |
| --- | --- | --- |
| **健康** | 索引、容器、大小和音频时间都没有问题。 | 不做任何事。 |
| **可在此修复** | Evey 能在这台服务器上修复的缺陷。 | **全部修复** 在后台处理它们。 |
| **信息** | 对文件测得的、Evey 不会自行改写的情况。 | 不做任何事。把它标记为已看过。 |

没有第三种会给你留下一件差事的结论。Evey 无法据此采取行动的测量结果只是一条提示，而且测量也可能出错：如果文件播放正常，它就是正常的。

### 可在此修复

- **缺少跳转索引**，或者索引无法使用。症状是跳转或继续播放很慢。索引会在一个临时副本中重建，副本经过完整检查（轨道、时长、索引）后再替换文件。
- **容器错误**：这个 `.mkv` 实际上是 MP4 或 MOV 文件。它会被重命名为 `.mp4`，媒体库也会随之更新；不会改写任何内容。
- **损坏片段**：文件中间的一段损坏区域。修复会跳过它，并重新同步其后的内容，因此这些字节会永久丢失。修复对话框会明确询问（**同时重新同步 N 个损坏文件**）；不勾选时，损坏的文件不会被触碰。同样的规则也适用于损坏只在改写时才出现的文件（**修复时发现损坏**）：扫描只读取文件头，无法发现它。
- **轨道按块存放**：先是几分钟的视频，然后是几分钟的音频，而不是并排交错。没有播放器能越过第一个块。**重新交错轨道** 会在不重新编码的情况下把它们并排改写，并在替换文件之前检查每个数据包都已写入。

### 信息

- **下载不完整**：文件的结尾从未到达。它能播放到截断处。没有工具能找回缺失的部分；只有源文件可以。
- **跳转粗糙**：重建后的索引仍有一个空洞，通常在片尾字幕处。跳到空洞中会落在它的边缘；其他地方的跳转都是精确的。
- **音轨从 +N 秒开始**：一条音轨在画面之后才开始。配音就是这样与某个剪辑版本对齐的，所有播放器都会照此播放。Evey 从不改写它。
- **音轨相差 N 秒**：文件自身的各条音轨互不一致，所以其中一条位置不对。任何测量都无法判断是哪一条。
- **声音与画面相差 N 秒**：一条音轨偏离了字幕（按画面对时）所标示的对白位置。
- **音轨被拉到 0**：之前的一次修复把某条音轨按其声明的延迟向前拉回时留下的标记。如果配音现在提前了，被移除的那段时间已经不在文件中。
- **音频 -N 秒**：一条音轨在画面结束之前就结束了。播放时会用静音填补空缺。
- **尾部多余字节**：文件内容结束之后多出的字节。播放正常。
- **无法读取**：扫描无法读取该文件（文件缺失、不可读，或者解析器拒绝的容器）。检查挂载或源文件。

## 用眼睛检查同步

对于三种音频提示，文件所在行的 **检查同步** 会在服务器上生成一段短片：选择一个时刻、一条音轨和一个要尝试的偏移量，然后观看，必要时可以放慢。比较各条音轨能说明它们是否一致，却永远无法说明哪一条跟随画面；只有观看才能确定。

**对该音轨应用 N 秒** 会把那条音轨按所选偏移量移动。这项更改被记录为你的判断，而不是测量结果，**历史** 可以撤销它。

## 标记为已看过

**已看过，不再提示**（单个文件）和 **全部标记为已看过**（一组）会把一条信息类提示从 **待处理** 视图中移除。只有提示可以被标记：可修复的缺陷会被修复。标记属于文件当前的状态：如果文件的大小或日期发生变化，下一次扫描会重新诊断它。**重新提示** 会撤销标记。

表格上方的视图（**待处理**、**可修复**、**信息**、**已看过**、**备份**、**全部**）和搜索框是处理大型媒体库的方式：**待处理** 就是待办清单。

## 扫描

扫描读取每个文件的开头（几 KB），并对没有变化的文件沿用上一次的答案。**磁盘占用** 设置节奏：

- **轻量**：一次一个文件，然后暂停与读取同样长的时间。磁盘大约一半时间是空闲的，这样别人可以继续观看。
- **快速**：同时处理多个文件，不暂停。在分布于多块磁盘的媒体库上大约快三倍，但在此期间播放可能会卡顿。

有两种情况会让扫描重新诊断所有文件：文件发生了变化，以及 Evey 的新版本改变了检查方式。因此在这样的更新之后，大型媒体库的第一次扫描会很长；之后的扫描又会变快。

## 备份、历史与撤销

**保留备份** 默认开启：每个被改写的文件都会在旁边以 `.mkvgobak` 保留原文件。**还原** 恢复一个文件，**全部还原** 恢复所选范围，**删除备份** 会永久删除它们。关闭时，一次运行期间只存在最近的几个副本，并在运行结束时删除；此时每次修复在替换文件之前都会经过更深入的验证。如果为每个文件保留副本会占满卷，页面会在运行之前提示。

**修复日志** 列出整个媒体库中每次修复对文件字节所做的更改；**历史** 显示单个文件的更改。有些更改可以在那里撤销，无需任何副本：

| 更改 | 撤销 |
| --- | --- |
| 音轨被移动 | 应用完全相反的移动。 |
| 重命名为 `.mp4` | 改回原来的名称。 |
| 重建索引 | 无需撤销：画面和声音都未被改动。 |
| 已跳过损坏片段 | 只有备份能找回丢失的字节，所以这种修复总是保留一个备份。 |

修复会写入你的媒体文件夹。它们必须以读写方式挂载到容器中（卷上不能有 `:ro`）；在一次遇到只读卷的运行之后，页面会提示。扫描在两种情况下都能工作。

## 通过命令行

同样的引擎在运维 CLI 中也可以使用（见 `cli.md`）：

- `evey admin reindex-no-cue --root <dir> [--apply] [--resync]` 重建缺失的跳转索引，除非给出 `--apply`，否则只是试运行；
- `evey admin validate-streaming --root <dir>` 输出只读的流媒体就绪报告。
