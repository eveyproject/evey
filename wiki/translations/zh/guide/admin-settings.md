# 管理

管理面板（头像菜单，然后是**管理**）是管理员日常运维服务器的地方。几乎所有内容都存储在
数据库中：容器更新后依然保留，而且大多数设置立即生效。如果某项设置只有在重启后才生效，
面板会注明（`docker compose restart`）。

本页按面板菜单的顺序，停在那些真正重要的设置上。服务器启动前就必须确定的事项（公网 URL、
受信任的代理、文件所有者），请参见[配置](../configuration.md)。

## 仪表盘与系统

### 仪表盘与正在播放

**仪表盘**显示版本、机器信息以及当前正在发生的事情。**正在播放**列出每一个进行中的流：谁、
看什么、在哪台设备上、以什么方式 - **直接播放**（原样文件）、**直接串流**（重新封装，画面
不变）或**转码**（经过转换）- 逐条音视频轨列出，并标明所用的引擎和显卡。你可以停止某个会话，
或给观众发一条消息。

### 远程访问

谁可以从你的家庭网络之外连接进来。

| 设置 | 作用 |
| --- | --- |
| **启用远程访问** | 关闭：地址不在你本地网络内的人，每个页面都会收到错误。开启：他们可以像其他人一样登录。 |
| **外部 URL** | 公网地址，当它与服务器启动时使用的地址不同时填写。 |
| **LAN 网络** | 被视为"家里"的地址段。默认已包含私有地址段；如果某个 VPN（Tailscale、WireGuard）的用户应算作家里人，就在这里加上它的地址段。 |
| **最大远程码率** | 家外观众的码率上限，单位 kbit/s（0 = 不限）。私有地址永远不受限。 |

如果你不去动它，服务器会在启动时决定：给了公网地址就开启远程访问，否则关闭。如果服务器能
从互联网访问、但远程访问是关闭的，页面会用红色警告。在反向代理后面，只有代理把客户端的
真实地址转发过来时，这才有效 - 参见
[反向代理](../reverse-proxy.md#real-client-ips-and-the-remote-access-gate)。

远程访问是关于"谁能访问服务器"的选择，而不是一道防护：保护媒体库的是登录。

### 服务器配置

该页面把服务器自身的设置分成若干卡片：

| 卡片 | 值得了解的设置 |
| --- | --- |
| **语言和地区** | 界面的默认语言、适用哪个国家的年龄分级，以及标题和简介的语言。 |
| **主页信息流** | 主页显示哪些行、按什么顺序、每行多少项。扩展可以添加行。 |
| **邮件 / SMTP** | 用于邀请和重置密码的外发邮件。参见[通知](../notifications.md)。 |
| **Trickplay 缩略图** | 生成进度条的预览图。默认开启。 |
| **分配的算力** | 后台工作加在一起最多能占用多少处理器：**25 %**（温和，默认）或 **50 %**（加速，适合没人观看时）。某项繁重任务（新媒体分析、缩略图、片头检测、复杂度分级）可以单独分配份额。从下一项开始生效。有人观看时后台工作会暂停。 |
| **内存配置** | **低**会挂起空闲的扩展以节省内存；**自动**会在内存低于 3 GB 的机器上选择它。 |
| **后台工作** | 暂停后台处理并控制其节奏（关键帧索引、编码 level）。启动时读取：修改后请重启。 |
| **封面下载** | 把海报和背景图转换为 WebP 保存在服务器上，而不是每次都从互联网加载。 |
| **解析器标记** | 当你的文件带有文件名解析器不认识的标签时，额外需要去掉的发布标签和版本名。 |
| **API 密钥** | TMDB（内置一个共享密钥）、OMDb、OpenSubtitles、TheIntroDB。 |
| **片头跳过提供商** | 在运行服务器自己的检测之前，先用社区数据库（TheIntroDB，其次 IntroDB）获取片头、前情提要和片尾的时间点。切换后请重启。还可以把服务器有把握的检测结果回传给 TheIntroDB。 |
| **服务器设置** | 服务器名称、登录与全局速率限制、日志级别、文件监控与扫描间隔、**自动跳过片头**（默认关闭：开启后每个播放器都会自行跳过检测到的片头）、**跳过预告片段**、历史和统计的保留时长、**转码缓存预算**（默认 10 GB），以及软件 AV1 的上限。 |
| **更新** | 每 6 小时检查一次是否发布了更新的镜像，并通知你。Evey 从不自动更新自己。 |

卡片下方的**配置条目**列出每一个原始的键值设置，以应对某个有文档的键没有专属卡片的少见情况。

### 转码

服务器如何转换视频。

- **编码校准**显示服务器对自己的测量结果：用软件和显卡分别能实时转换的最高分辨率，以及显卡
  支持哪些编码。**硬件加速**选择显卡（**自动**选用检测到的最佳设备，**关闭**则强制使用
  处理器）。加装显卡或把容器迁移到另一台机器后，请点**重新校准**。这里还有：**AV1 输出**
  （仅硬件）、Intel 的**低功耗编码器**，以及**视频码率上限**，并可为家外观众单独设置一个上限。
- **实时播放容量**是可以同时转码的视频数量。它是实测出来的；你只能调低。只转换声音的流不占
  名额，切换画质的观众始终只占一个名额。
- **后台转码任务**限制排队中的转码任务数量，与实时播放分开计算。
- **高级限制**在弱硬件上限制会话数和分辨率。启动时读取。
- **负载测试**模拟真实观众，测量服务器能承受多少。请只在没人观看时运行。

在 Docker 中配置显卡：[转码与硬件](../transcoding.md)。

### 转码缓存与系统健康

**转码缓存**显示转码在磁盘上留下的内容，并可清空。在一次改变视频转码方式的更新之后清空它，
可以确保没人拿到旧的转码结果。**系统健康**显示处理器、内存、带宽、存储以及正在使用的转码
容量。

## 媒体

- **媒体库**：添加、编辑、扫描、计划；元数据方面有**仅匹配孤立项**、**从 TMDB 重新匹配
  全部**和**修复系列**。参见[第一步](first-steps.md#add-your-libraries)。
- **图片缓存**：保存在服务器上的海报和背景图。
- **媒体健康**：对每个 MKV 和 WebM 文件做只读扫描，给出两种结论之一。**可修复**（缺少跳转
  索引、损坏的片段、实际是 MP4 的 `.mkv`）可以用**全部修复**一次性修好，每个修复过的文件都会
  把原文件保留为备份。**仅供参考**（下载不完整、音频偏移……）列出在这里无法修复的问题。修复会
  写入你的媒体文件夹，所以这些文件夹必须以读写方式挂载。更多内容见
  [媒体健康](../runbooks/media-health.md)。

在单个标题上，管理员还可以**编辑元数据**、更换海报，并手动调整**媒体片段**（片头、前情提要、
片尾）或重新运行检测。

## 用户与访问

- **用户**：创建、编辑、停用或删除账户；把每个账户限制在部分媒体库；限制其流媒体码率、个人
  资料数量以及每个个人资料的设备数量；查看其历史；**以此身份登录**以看到对方所见（会有横幅
  提醒，点**退出**即可返回）。
- **邀请链接**：一个链接，可选设置过期时间、使用次数、媒体库、个人资料上限以及管理员角色。
- **媒体请求**：用户请求的标题队列（同意、拒绝或推迟，并附备注），以及谁可以提出请求：默认
  所有人，可按用户设置例外。

## 集成

- **插件**：从 ZIP 文件安装。安装前，面板会显示扩展声明的权限以及静态分析的发现。每个
  扩展都可以：启用、更新、资源限制（内存、进程、磁盘、优先级）、日志。参见[扩展](../plugins.md)。
- **Webhooks**：发生某件事时（添加了一个标题、开始了一次播放……）调用你的某个 URL，可针对
  所有事件或选定的几个，如果你提供了 secret 还会签名。**测试**会发送一个 ping。
- **API 密钥**：供你自己的脚本和集成使用的密钥，每个都只限于你勾选的范围（读取媒体、控制
  播放、管理用户……）。密钥只在创建时显示一次。**API 文档**列出每个范围开放了什么，并允许
  你试用。

## 监控与维护

- **分析**：今天和本周的播放次数、活跃用户、最近 30 天最受欢迎的标题。
- **活动**：播放和管理操作的历史，以及正在进行的后台工作。
- **日志与调试**：搜索并实时跟踪服务器日志，可按领域筛选（播放、转码、扫描……）。用户报告
  问题时的第一站。
- **流媒体质量**：最近一天或一周里真实观众的播放情况 - 他们等待视频的频率、最常卡顿的标题，
  以及最吃力的设备类型。
- **备份与恢复**：创建备份、下载备份、恢复某个备份，或从文件恢复。计划与保留策略见
  [备份](../backups.md)。

当面板本身没有响应时，同样的维护操作可以通过命令行完成：[命令行](../runbooks/cli.md)。
