# 语言与无障碍

如实说明 Evey 在国际化（i18n）和无障碍（a11y）方面的现状：什么可以用、如何工作，以及什么还没有。这是一个由一个人构建和维护的自托管项目：请尤其把无障碍视为*尽力而为，而非经过认证*。

---

## 国际化（i18n）

### 什么会翻译，什么不会

- **会翻译：** 界面本身：按钮、菜单、设置、错误消息、电子邮件和推送通知的文字。
- **Evey 不翻译：** 媒体元数据（标题、剧情简介、类型）来自你的元数据提供商（TMDB/OMDb），使用设置向导或 **Admin → 服务器配置 → 语言和地区** 中设置的 **元数据语言**（`EVEY_METADATA_LANGUAGE` 只是默认值），它与界面语言相互独立。你自己的媒体库、文件名以及你输入的任何内容都按原样保存。

所以界面可以是法语，而一部电影的简介是英语（或者反过来）：它们是两个独立的设置。

### 支持的界面语言

六种：**英语 (en)**、**法语 (fr)**、**德语 (de)**、**西班牙语 (es)**、**中文 (zh)**、**印地语 (hi)**。英语是源语言，也是后备语言：其他语言中缺少的任何字符串都会退回英语，而不是显示空白或键名。

### 工作原理

- **唯一的事实来源：** 仓库根目录下的 [`/i18n/<locale>/*.yaml`](../i18n)，按命名空间划分（`common`、`auth`、`media`、`player`、`admin`、`errors`、`notifications`、`mobile`、`downloads`、`requests`）。同一份目录驱动所有界面。
- **服务器** 加载它并在 `GET /api/v1/i18n/{locale}` 提供，同时直接用它来翻译 API 错误消息和通知文字。
- **网页、移动和电视应用** 从这个端点加载翻译（i18next + http-backend），在本地缓存，并让 `<html lang>` 与当前语言保持同步，以便辅助技术朗读正确的语言。
- 语言依次取自你的账户偏好、浏览器或设备的语言（解析 `Accept-Language`，去掉地区：`fr-FR` → `fr`）、**Admin → 服务器配置 → 语言和地区** 中的 **服务器语言**（它也决定新账户的语言），最后是英语。
- 插值和复数使用 i18next（`{{count}}` 等）。

### 如实说明的限制

- **完整程度不一。** 英语是权威版本，总是完整的；其他五种语言借助检查脚本手动保持同步，但一个全新的功能可能先以英语上线，在翻译之前退回英语显示。
- **还没有从右到左的语言。** 没有阿拉伯语、希伯来语或波斯语，布局也没有为 RTL 构建或测试过：添加一种这样的语言是实实在在的工作（CSS 逻辑属性、`dir` 处理），而不只是一个翻译文件。
- **翻译没有经过专业审校。** 它们是社区或维护者水平的质量。欢迎指正。
- **本地化格式只做了一部分。** 日期和数字依赖平台的 `Intl` 或浏览器的语言设置，并没有在每个界面上统一接入。

### 添加或修正一种语言

1. 把 `i18n/en/` 复制到 `i18n/<your-locale>/` 并翻译 YAML 的值（保留键名）。
2. 把该语言加入 [`internal/pkg/i18n/i18n.go`](../internal/pkg/i18n/i18n.go) 中的允许列表（`supportedLocales`）。
3. 让所有语言的键集合保持一致：否则一致性检查会失败。

## 无障碍（a11y）

### 现状

Evey 使用语义化 HTML、ARIA 标签和 React Native 的无障碍属性构建，下面列出的几项是有意为之的。但它**没有**按照 WCAG 进行正式审计，测试套件中**没有自动化的无障碍测试**，也**没有**用屏幕阅读器进行系统性的测试。它的一部分很可能可以配合辅助技术使用；另一部分很可能不行。如果你依赖辅助技术，请预期会有不完善之处，并请报告具体情况。

### 已经具备的

- **减少动态效果：** 全局遵循 `prefers-reduced-motion: reduce`：当你的操作系统要求时，动画和过渡实际上会被禁用。
- **辅助技术的语言：** `<html lang>` 跟随当前的界面语言。
- **键盘（播放器）：** 完整的键盘控制，带有屏幕上的快捷键叠加层（`?`），在你在输入框中打字时快捷键会被暂停。
- **带标签的控件：** 只有图标的按钮和滑块在网页上带有 `aria-label`，在移动端带有 `accessibilityLabel`/`accessibilityRole`（大部分交互控件，并非全部）。
- **主题：** 内置五个主题（默认深色、AMOLED、深红、默认浅色、浅蓝）；更多主题可通过主题插件获得。
- **Android TV：** 为遥控器导航提供方向键焦点处理。

### 如实说明的不足（尚未完成）

- **没有用屏幕阅读器检查过。** NVDA/VoiceOver/TalkBack 的使用流程未经验证；一些自定义组件（菜单、模态框、进度条、轨道选择器）可能无法正确朗读其状态或角色。
- **焦点管理没有经过审计。** 焦点可见样式以及对话框和叠加层中的焦点顺序在某些地方不一致。
- **只对内置主题测量了对比度。** 一个单元测试（`frontend/packages/theme/src/contrast.test.ts`）要求每个内置主题的强调色、三组文字色阶和危险色组，在背景和两种表面上都达到 WCAG AA 4.5:1；电视应用会重新检查其派生的令牌。主题插件以及插件在运行时注入的颜色不会被检查：自定义主题仍可能在某些地方不达标。不以 AAA 为目标。
- **除了浏览器或操作系统的缩放之外，没有应用内的文字缩放**，也没有专门的高对比度模式。
- **移动端的字幕样式有限**（这是底层 `expo-video` 播放器的限制），不过字幕轨道本身可以播放。

### 报告问题

告诉我们页面或界面、具体的控件、你的预期，以及你使用的辅助技术及其版本。具体的报告会被修复；"它不无障碍"这样的描述无法采取行动。无障碍修复按尽力而为的方式处理。
