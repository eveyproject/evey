# एक्सटेंशन सैंडबॉक्स - आपके सर्वर के लिए कौन सा सेटअप

Evey तीसरे पक्ष के एक्सटेंशन को एक सैंडबॉक्स के भीतर चलाता है। **लगभग हर किसी के
लिए जवाब है: डिफ़ॉल्ट ही रहने दें।** सर्वर आपकी मशीन पहचानता है और अपने आप सबसे
मज़बूत अलगाव चुनता है जो वह दे सकता है। आगे तभी पढ़ें जब आप कोई **पुराना NAS**
चलाते हों, Evey को **Docker के बिना** चलाते हों, या **और कसना** चाहते हों।

पूरे तकनीकी मॉडल के लिए [SECURITY.md](../SECURITY.md) देखें। यह पृष्ठ सीधी भाषा
में फ़ैसला लेने की गाइड है।

---

## आपकी रक्षा क्या करता है (सीधे शब्दों में)

आप जो एक्सटेंशन इंस्टॉल करते हैं, वह एक डिब्बे में बंद रहता है। आपकी मशीन के
हिसाब से यह डिब्बा:

- **सीमित करता है कि वह किन फ़ाइलों को छू सकता है** - उसे अपना फ़ोल्डर और चलने के
  लिए ज़रूरी सिस्टम लाइब्रेरी दिखती हैं, और कुछ नहीं (न आपका मीडिया, न आपके राज़,
  न दूसरे एक्सटेंशन)।
- **ख़तरनाक सिस्टम कार्रवाइयाँ रोकता है** - दूसरी प्रक्रियाओं को debug करना, कर्नेल
  मॉड्यूल लोड करना, घड़ी बदलना, डिस्क माउंट करना आदि कर्नेल स्तर पर ठुकरा दिए जाते
  हैं।
- **नेटवर्क काट देता है**, जब तक एक्सटेंशन ने उसे साफ़ तौर पर न माँगा हो (और आपने वह
  अनुमति मंज़ूर न की हो)।
- **CPU, मेमोरी, डिस्क और प्रक्रियाओं की संख्या पर सीमा लगाता है**, ताकि बेक़ाबू
  एक्सटेंशन सर्वर को न गिरा सके।
- **आपके राज़ पढ़ने लायक़ नहीं रहने देता** - साइन-इन पर हस्ताक्षर करने वाली कुंजी और
  बैकअप।

इसके ऊपर: एक्सटेंशन **सिर्फ़ व्यवस्थापक इंस्टॉल कर सकता है**, उन्हें संदिग्ध कोड के
लिए **स्कैन** किया जाता है, और उनके चलने से पहले आप **उनकी अनुमतियाँ मंज़ूर** करते
हैं।

**देखें कि असल में क्या लागू है:** Admin → Plugins → Security Dashboard *होस्ट
सैंडबॉक्स* दिखाता है - वह मोड जिस पर `auto` पहुँचा (`landlock`, `bubblewrap` या
`basic`), हर जाँच के नतीजे के साथ। अगर वह **basic** दिखाए, तो आपका होस्ट पाथ के
हिसाब से फ़ाइल सिस्टम अलगाव नहीं देता (एक्सटेंशन सिर्फ़ UID-drop + seccomp के साथ
चलते हैं); जाँचें बताती हैं क्यों, और नीचे के खंड बताते हैं कि इसे कैसे ठीक करें।

## अपनी स्थिति चुनें

| आपका सर्वर | बिना कुछ किए क्या मिलता है | कुछ करना है? |
|---|---|---|
| **Docker में आधुनिक Linux** (कर्नेल ≥ 5.13 - लगभग ~2021 के बाद का सब कुछ) - *सामान्य स्थिति* | **सबसे मज़बूत अलगाव** (Landlock), अपने आप। | **कुछ नहीं।** डिफ़ॉल्ट रहने दें। |
| **Docker में पुराना NAS** (जैसे पुराना Synology, कर्नेल < 5.13) | अच्छा अलगाव, **फ़ोल्डर-दर-फ़ोल्डर फ़ाइल दीवारों के बिना**। राज़, नेटवर्क और सिस्टम कार्रवाइयाँ फिर भी बंद रहती हैं। | वैकल्पिक: राज़ों की दोहरी सुरक्षा के लिए **uid separation** चालू करें (नीचे)। |
| **कोई भी Linux, बिना Docker** (bare-metal) | **सबसे मज़बूत अलगाव**, अपने आप (आधुनिक कर्नेल पर Landlock, वरना bubblewrap namespaces)। | [बिना कंटेनर वाली गाइड](../deployment-bare-metal.md) का पालन करें। |

कैसे जानें कि आपके हिस्से कौन सा आया: **Admin → Plugins** खोलें - सुरक्षा पैनल का
बैज असल में लागू सैंडबॉक्स मोड दिखाता है: `landlock` या `bubblewrap` मतलब मज़बूत,
`basic` मतलब "पुराना NAS" वाली स्थिति।

## वह एक बटन जिसे आप शायद छुएँ: uid separation

**यह क्या करता है, सीधे शब्दों में:** एक्सटेंशन को Evey से **अलग उपयोगकर्ता खाते**
के तहत चलाता है, ताकि वह Evey की गुप्त फ़ाइलें भौतिक रूप से पढ़ ही न सके - भले ही
और कुछ उसे न रोके।

**यह कब मायने रखता है:** सिर्फ़ **फ़ोल्डर-दर-फ़ोल्डर फ़ाइल दीवारों के बिना वाली पुरानी
मशीन** पर (यानी `basic` स्थिति)। आधुनिक मशीनों पर फ़ाइल दीवारें पहले ही राज़ों को
पहुँच से बाहर रखती हैं, इसलिए वहाँ uid separation बस एक फ़ालतू अतिरिक्त परत है।

**सेटिंग** - `EVEY_PLUGINS_UID_SEPARATION`:

| मान | मतलब | कब इस्तेमाल करें |
|---|---|---|
| `auto` *(डिफ़ॉल्ट)* | **सिर्फ़ तभी चालू होता है जब सच में ज़रूरत हो** (`basic` स्थिति)। जहाँ फ़ालतू है वहाँ बंद। | **इसे ऐसे ही रहने दें** - यह हर मशीन पर सही करता है। |
| `on` | **हमेशा चालू**, आधुनिक मशीनों पर भी - फ़ाइल दीवारों के ऊपर राज़ों के चारों ओर एक दूसरी, स्वतंत्र दीवार। | आप अधिकतम दोहरी सुरक्षा चाहते हैं और नीचे की छोटी क़ीमत स्वीकार करते हैं। |
| `off` | **कभी नहीं।** | कोई ख़ास एक्सटेंशन इसके तहत ग़लत बर्ताव करता है (कम ही)। |

**पेंच:** uid separation **Docker की `no-new-privileges` सख़्ती वाली सेटिंग के साथ
नहीं चलता** - एक चुनें। अगर आपका सेटअप इसे किसी पुरानी मशीन (`basic`) पर नहीं दे
पाता, तो Evey एक्सटेंशन को आपके राज़ों के बगल में चलाने के बजाय **उसे शुरू करने से
मना कर देता है**; आधुनिक मशीन पर वह चेतावनी लॉग करता है और एक्सटेंशन सामान्य रूप
से चलाता है (बस आपको अतिरिक्त दीवार नहीं मिलती)। आधिकारिक इमेज में ज़रूरी सब कुछ
पहले से है; आपको सिर्फ़ यह वेरिएबल सेट करना है।

**`on` की छोटी क़ीमत:** एक्सटेंशन एक अलग खाते से चलता है, इसलिए जो एक्सटेंशन *अपने
ही फ़ोल्डर के भीतर* अस्थायी फ़ाइलें लिखता है, वह अटक सकता है। ऐसा हो तो `off` करें।
(इसीलिए डिफ़ॉल्ट `auto` है - वह यह जोखिम वहीं लेता है जहाँ सचमुच फ़ायदा हो।)

## जोखिम, सीधे शब्दों में

एक **दुर्भावनापूर्ण** एक्सटेंशन क्या कर सकता है और क्या नहीं - हर स्थिति के हिसाब से:

**आधुनिक Linux (Docker या bare-metal):**
बुरा एक्सटेंशन पूरी तरह बंद रहता है। वह आपके राज़ **नहीं** पढ़ सकता, दूसरे
एक्सटेंशन की फ़ाइलें **न** देख सकता है न छू सकता है, मनमाने नेटवर्क कॉल **नहीं** कर
सकता, और सिस्टम से छेड़छाड़ **नहीं** कर सकता। बाहर निकलने का इकलौता असली रास्ता
Linux **कर्नेल** की कोई गंभीर ख़ामी है - यह बात *हर* उस सैंडबॉक्स पर लागू होती है जो
पूरी वर्चुअल मशीन नहीं है।

**Docker में पुराना NAS, फ़ोल्डर-दर-फ़ोल्डर दीवारों के बिना (`basic`):**
- ✅ आपके **राज़ सुरक्षित रहते हैं** (लॉगिन कुंजी, बैकअप) - *ख़ासकर अगर आप uid
  separation `on` करें*।
- ✅ अनुमति न हो तो एक्सटेंशन को **कोई नेटवर्क नहीं** मिलता।
- ✅ **ख़तरनाक सिस्टम कार्रवाइयाँ** कर्नेल पर **फिर भी रुकी रहती हैं**।
- ⚠️ पर फ़ोल्डर-दर-फ़ोल्डर दीवारों के बिना, बुरा एक्सटेंशन **आम, ग़ैर-गुप्त फ़ाइलें पढ़
  सकता है**, **चलती प्रक्रियाओं की सूची देख सकता है**, और - क्योंकि एक्सटेंशन एक ही
  खाता साझा करते हैं - संभवतः **किसी दूसरे एक्सटेंशन की फ़ाइलें पढ़ या बिगाड़ सकता
  है**।
- **निचोड़:** ऐसे होस्ट पर सिर्फ़ भरोसेमंद एक्सटेंशन इंस्टॉल करें, या पूरी फ़ाइल
  दीवारों के लिए आधुनिक कर्नेल पर जाएँ।

## कॉन्फ़िगरेशन के उदाहरण (कॉपी/पेस्ट)

ये आपकी `.env` (Docker compose) में या `EVEY_*` environment वेरिएबल के रूप में जाते
हैं।

**1. सामान्य आधुनिक सर्वर - अनुशंसित (कुछ न करें):**
```bash
# Defaults are correct. Optionally make it explicit:
EVEY_PLUGINS_SANDBOX_MODE=auto          # picks the strongest available
# EVEY_PLUGINS_UID_SEPARATION=auto      # (default) on only where needed
```

**2. पुराना NAS, राज़ों की अधिकतम सुरक्षा:**
```bash
EVEY_PLUGINS_SANDBOX_MODE=auto
EVEY_PLUGINS_UID_SEPARATION=on          # force the secret wall on
# and do NOT set no-new-privileges in your compose security_opt
```

**3. आधुनिक सर्वर पर अधिकतम दोहरी सुरक्षा (दोनों दीवारें):**
```bash
EVEY_PLUGINS_SANDBOX_MODE=auto          # → landlock
EVEY_PLUGINS_UID_SEPARATION=on          # add the independent uid wall on top
```

**4. कोई ख़ास मोड तय करना (उन्नत):**
```bash
EVEY_PLUGINS_SANDBOX_MODE=landlock      # refuse to start plugins if Landlock is unavailable (fail‑closed)
```

**5. कोई एक्सटेंशन uid separation के तहत टूटता है:**
```bash
EVEY_PLUGINS_UID_SEPARATION=off
```

**6. संसाधन सीमाएँ (सभी बाद में Admin → Plugins से बदली जा सकती हैं):**
```bash
EVEY_PLUGINS_MEMORY_MB=256              # max RAM per plugin
EVEY_PLUGINS_PIDS_MAX=64                # max processes/threads
EVEY_PLUGINS_DISK_MAX_MB=100            # max install‑dir size (0 = off)
EVEY_PLUGINS_CPU_NICE=10                # scheduling priority 0-19 (higher = nicer)
```

## चलते-चलते सैंडबॉक्स मोड बदलना

आप **Admin → Plugins** के **Resource limits** कार्ड से मोड बदल सकते हैं। चल रहे
एक्सटेंशन **अपने आप फिर से शुरू** होते हैं ताकि नया मोड तुरंत लागू हो (हाथ से बंद/
चालू करने की ज़रूरत नहीं)। सुरक्षा बैज असल में लागू मोड दिखाता है। अगर कोई एक्सटेंशन
नए मोड में नहीं चल पाता (जैसे आपने Docker पर `bubblewrap` चुना, जहाँ उसे विशेषाधिकार
चाहिए), तो वह डैशबोर्ड में **त्रुटि** के रूप में दिखता है - बस वापस बदल दें।

## जाँचें कि यह काम कर रहा है

```bash
# the launcher carries the capability used for uid separation:
docker exec evey-server getcap /evey-plugin-launcher        # → cap_setuid=ep

# which user a running plugin runs as (evey = shared with server, evey-plugin = separated):
docker exec evey-server ps -o user,pid,args | grep -v grep | grep -iE "node|python"

# the sandbox mode actually in force: the Security badge on the Admin → Plugins page.
```
